# 모아봄

드라마, 영화, 음악을 감상한 날짜에 포스터와 별점, 감상평을 남기는 웹 다이어리입니다. 한국어 HTML·CSS·JavaScript, Supabase Auth와 Postgres, Vercel Functions를 사용합니다.

[모아봄 열기](https://alephmyappproject.vercel.app/)

## 기록하기

1. 이메일과 비밀번호로 가입하고 로그인합니다. 이메일 확인 필요 여부는 Supabase Auth 프로젝트 설정에 따릅니다. 로그인 창에서 비밀번호 변경 메일도 요청할 수 있습니다.
2. 캘린더의 날짜나 **기록하기**를 누르고 드라마, 영화, 음악, 음악과 장면 중 하나를 고릅니다. 음악과 장면에서는 작품 종류와 곡, 장면 설명, 연결 이유를 따로 선택합니다.
3. 제목이나 가수를 검색하고 결과를 선택합니다. 제공되는 포스터, 날짜, 소개 또는 앨범 정보가 채워집니다. 직접 입력도 가능합니다.
4. 감상 날짜, 별점, 감상평을 입력하고 저장합니다. 같은 별을 다시 누르면 평가가 해제됩니다. 기본 공개 범위는 비공개입니다.
5. 포스터를 눌러 상세를 열고 수정·삭제합니다. 같은 날 보이지 않는 기록은 `+N개`에서 모두 열 수 있습니다.

### 표지와 음악

- 작품 검색은 TMDB 한국어 카탈로그를 사용합니다. 서버가 제공하는 다음 결과 페이지와 동명 작품의 개봉·방영일, 원제가 표시됩니다.
- **포스터 바꾸기**에서 TMDB의 다른 이미지, 직접 업로드 또는 HTTPS 주소를 선택할 수 있습니다. 구글 이미지 검색은 별도 창에서 열립니다. 사용 권한이 있는 이미지를 이용하세요.
- JPG·PNG·WebP 파일은 최대 10MB까지 선택할 수 있습니다. 브라우저에서 최대 480×720px JPEG로 압축하며, 저장하는 데이터 URL은 115,000자 미만입니다. 원본 파일을 전송하지 않습니다. 공개 기록의 표지는 다른 사람도 볼 수 있습니다.
- 음악은 MusicBrainz와 Apple 음악 카탈로그를 검색합니다. 한국어 검색은 Apple의 미국·한국 카탈로그 결과를 함께 살핍니다. 앨범 정보와 표지는 제공되는 경우 표시합니다.
- 일반 음악과 음악과 장면 모두 유튜브 원본 영상 링크를 선택적으로 연결할 수 있습니다. 링크만 저장합니다.

## 기록 다시 보기

- **포스터 캘린더**에서 이전 달, 다음 달, 오늘로 이동하고 기록 종류를 고를 수 있습니다. 요약은 선택한 달의 네 종류와 평가한 기록의 평균 별점, 전체 누적 기록 수를 표시합니다.
- **나의 기록**에서 전체 기록·작품별·음악별 보기, 검색·정렬과 JSON/CSV 내보내기를 사용할 수 있습니다. 백업은 로그인한 계정의 데이터만 브라우저로 내려받습니다. 이전 게스트 기록이 남아 있는 기기에서는 로그인 후 비공개로 가져올 수 있습니다.
- **모두의 기록**은 비회원에게도 열려 있습니다. 검색·종류·정렬은 전체 공개 기록을 대상으로 수행하며, 한 번에 24개씩 불러옵니다. 공개 링크 `?record=<UUID>`와 공개 상세는 열 때마다 현재 공개 여부를 다시 조회합니다.

## 실행과 배포

프로젝트 루트의 HTML·CSS·JavaScript를 정적 서버로 실행할 수 있습니다. 검색과 포스터 갤러리까지 사용하려면 기존 Vercel 프로젝트 또는 `vercel dev`에서 실행합니다.

- 클라이언트 설정은 `config.js`의 기존 Supabase URL과 publishable key를 사용합니다.
- `ALEPH_Task`의 `public.taste_journal_records`를 그대로 사용합니다. 삽입·수정·삭제는 소유자에게만 허용됩니다. 기록 수정 충돌은 기존 `version`과 DB 트리거로 감지합니다.
- Supabase Auth의 이메일 확인·비밀번호 복구 리디렉션에는 운영 URL을 허용해야 합니다. 메일 수신은 해당 프로젝트의 이메일 발송 설정을 따릅니다.
- TMDB 읽기 토큰 `TMDB_READ_TOKEN`은 Vercel 서버 환경변수에만 설정합니다. `api/search.js`와 `api/posters.js`가 사용합니다.
- `tests/browser.mjs`는 Chromium과 운영 버전의 Supabase JS SDK로 네 가지 기록 흐름, 공개 링크 재조회 및 반응형 레이아웃을 검사합니다. 이 검사는 별도의 테스트 HTTP 서버를 사용하며 운영 DB나 실제 이메일을 사용하지 않습니다.

This product uses the TMDB API but is not endorsed or certified by TMDB.

## 이번 화면 개선 (2026-11-07)

- 기존 HTML/CSS/JavaScript 및 Supabase 테이블은 그대로 유지하고 포스터 달력을 중심으로 봄 에디토리얼 디자인을 적용했습니다. 캐릭터나 제삼자 일러스트를 사용하지 않습니다.
- 월 이동 화살표와 오늘 버튼의 정렬·크기를 분리하고 작은 화면에서 겹치지 않도록 레이아웃을 조정했습니다. 키보드 포커스 표시는 유지합니다.
- 사이드 메뉴와 하단 문구는 고정 위치 대신 일반 페이지 흐름 안에 두어 본문과 함께 스크롤되도록 했습니다.
- 캘린더에 **내 기록 검색**을 추가했습니다. 저장된 제목·음악·메모를 검색하면 최대 8개 결과가 표시되며, 결과를 누르면 해당 달로 이동하고 감상 상세를 엽니다. 로그인 후 자신의 기록을 불러온 범위 안에서 검색합니다.
- 달력과 오른쪽 통계·최근 기록 카드의 시각적 우선순위, 기록 화면, 버튼 및 모바일 레이아웃을 다시 정리했습니다.
- 확인: JavaScript 구문 확인, HTML ID 중복 및 스크립트 참조 요소 검사, Vercel 운영 배포 200 응답, 실제 TMDB 드라마 및 음악 검색 API의 정상 응답을 확인했습니다.
- **미확인:** 실제 계정으로 기록 생성·수정·삭제, 이메일 인증, 접근 권한을 포함한 전체 브라우저 E2E 테스트는 이번 작업에서 실행하지 않았습니다. 테스트하지 않은 사항을 완료라고 간주하지 마세요.

## 공개 테스트 기록 10개 (2026-11-07)

- **모두의 기록**에 관리용 테스트 샘플 10개를 실제로 게시했습니다. 로그인하지 않은 사람도 볼 수 있습니다.
- 드라마 4개, 영화 3개, 음악 2개, 음악과 장면 1개이며 작품 정보와 포스터, 예시 별점·감상평·태그를 담았습니다.
- 공개 샘플은 관리용 예시 콘텐츠입니다. 예시 문구를 화면에 붙이지 않으며 실제 사용자의 감상으로 간주하지 않습니다.
- 공개 샘플은 회원의 개인 기록 테이블이 아닌 'taste_journal_demo_public'에 저장되며, 읽기 전용입니다. 비공개 기록이나 계정에 간섭하지 않습니다.
- 조회는 security_invoker가 적용된 'taste_journal_public_feed' 뷰로 이루어집니다. 실제 사용자의 공개 기록과 샘플을 함께 보여줍니다. 기존 RLS 정책을 유지합니다.
- 공개 샘플에는 회원 ID를 연결하지 않았습니다. 임의 계정을 선택해 데이터를 넣거나 회원 명의로 가상의 리뷰를 생성하지 않습니다.
- 데모 레코드를 회원 계정에 추가하는 버튼은 삭제했습니다. 운영에 필요한 샘플 관리와 사용자 데이터는 분리되어 있습니다.
- 샘플 감상 날짜는 UI 테스트용 날짜이며 실제 감상 이력을 의미하지 않습니다.


## 취향 추천·공개 콘텐츠 확장 (2026-11-07)

- **취향 추천** 메뉴에서는 본인의 기존 기록 중 별점 4점 이상인 항목을 참고합니다. 콘텐츠 종류 빈도와 태그 일치도를 기준으로 아직 기록하지 않은 공개 콘텐츠를 추천합니다. 추천 항목을 누르면 현재 공개 여부를 다시 확인하고 상세를 표시합니다. 음악과 장면 기록의 원본 작품도 이미 본 콘텐츠로 판단합니다.
- 본인 기록이 적거나 로그아웃한 상태라면 '공개 기록 기반 추천'으로 표시합니다. 추천은 공개 기록의 예시 별점·태그에 기반한 단순 규칙이며 외부 추천 서비스나 AI 모델 분석이 아닙니다.
- 취향 추천 화면에서 드라마·영화·음악 필터, 국내·해외 필터, 다시 추천받기, 다른 추천 더 보기를 지원합니다. 추천은 이용자 기록을 외부에 보내거나 별도 DB에 저장하지 않습니다.
- 공개 예시 기록을 **기존 10개에서 50개로 확대**했습니다. 새로 추가된 40개는 국내 30개와 해외 드라마·영화 10개입니다. 새 샘플은 드라마 17개, 영화 15개, 음악 6개, 음악과 장면 2개로 구성됩니다.
- 원래 회원 기록과 예시 기록은 물리적으로 다른 테이블에 분리되어 있습니다. 공개 피드 조회에는 security_invoker 뷰를 사용하며 비회원의 읽기 권한도 확인했습니다.
- 테스트 샘플의 날짜·평점·감상평은 실제 회원의 활동·평가를 의미하지 않습니다.
- 확인: Supabase에서 익명 역할로 읽은 공개 피드 52개(그중 예시 50개, 해외 10개), JavaScript 문법과 HTML 참조 요소 및 ID 중복 정적 검사. 실제 로그인 계정 기반 E2E 테스트는 별도로 수행해야 합니다.


## 단일 봄 디자인 개편 (2026-11-07)

- 별도의 '기록장 꾸미기' 메뉴와 테마 전환·localStorage 설정을 제거했습니다. 더 이상 벚꽃/초록/살구 테마 중 고르지 않으며 웹앱 전체에 하나의 봄 디자인이 적용됩니다.
- 과거 CSS에 반복 추가했던 테마별 덮어쓰기 규칙을 걷어내고 한 개의 CSS 파일에 통일된 **보태니컬 에디토리얼** 디자인을 적용했습니다. 회원 기록과 Supabase 스키마는 변경하지 않았습니다.
- 화면 구조는 기존 왼쪽 사이드바 대신 가로 탐색 메뉴를 사용합니다. 포스터 캘린더, 나의 기록, 모두의 기록, 취향 추천의 네 메뉴를 유지합니다.
- 진녹색 브랜드 헤더, 종이 질감의 대형 봄 기록장 배너, 식물도감 스타일의 카드와 달력, 강조되는 포스터, 모바일 가로 스크롤 탐색 메뉴로 새롭게 구성했습니다.
- 공용 기록 카드, 취향 추천, 기록 작성 다이얼로그의 시각 요소도 통일했습니다. 원래 작품 검색·회원 관리·저장·공개 기록은 그대로 사용합니다.
- 정적 검사에서 JavaScript 구문, HTML ID 중복과 JavaScript 참조 요소 누락이 없음을 확인했습니다. 실제 브라우저 레이아웃과 계정별 저장·수정은 추가적인 사용자 시나리오 확인이 필요합니다.


## 연결된 취향과 개인 보관함 기능 (2026-11-07)

- **취향 연결 지도**: 로그인한 사용자의 기존 작품·음악 기록과 음악과 장면 연결을 바탕으로 관계를 그립니다. 실선은 한 기록에 직접 연결된 작품과 음악, 점선은 작품·음악이 공유하는 취향 태그를 의미합니다. 각 노드를 눌러 기존 감상 상세를 열 수 있습니다. 최대 18개 콘텐츠와 최대 28개 연결을 시각화하며 데이터가 많을 때 세로 공간을 확장합니다.
- **양방향 추천**: 취향 추천 화면에서 '좋아한 작품 → 음악' 또는 '좋아한 음악 → 작품'을 선택할 수 있습니다. 기존 공개 기록을 후보로 사용하고, 직접 연결된 음악·작품과 공통 태그·별점을 우선 고려합니다. 외부 AI/음악 스트리밍 추천 API는 사용하지 않습니다.
- **순간 스크랩북**: 감상 기록 1개에 연결한 장면 제목·메모 및 선택적인 HTTPS 사진 주소를 별도 저장할 수 있습니다. 한 작품에 여러 장면을 독립적으로 기록할 수 있습니다.
- **마음 서랍**: 사용자가 이름과 설명을 만든 뒤 기존 감상 기록 여러 개를 선택해 함께 보관합니다.
- **취향 타임캡슐** 및 **미래의 나에게**: 메시지와 다시 읽을 날짜를 저장하고, 날짜 전에는 화면에서 내용을 가립니다. 이는 UI 잠금이며 종단 간 암호화나 강제적 비밀 보관은 아닙니다. 알림/이메일 발송도 현재 구현하지 않았습니다.
- 신규 테이블 `public.taste_journal_spaces`는 사용자 개인 소유 데이터만 허용하는 RLS 정책을 적용합니다. `anon`의 SELECT 권한을 허용하지 않았고, 로그인한 사용자만 자신의 데이터를 생성·조회·수정·삭제할 수 있습니다. 기존 `taste_journal_records`는 변경하지 않았습니다.
- 홈/추천 배너는 과도한 원형 장식·스탬프·중복 꽃 장식을 정리하고 높이·여백을 줄였습니다. 기존 봄 색상과 글꼴을 유지합니다.
- 정적 검사와 간단한 가상 DOM 단위 검사를 수행했습니다. 실제 계정으로 새 보관함 저장·수정·삭제를 수행하는 브라우저 E2E 테스트는 별도 확인이 필요합니다.


## 닉네임·사진 업로드·미래 기억 잠금 보완 (2026-11-07)
